These starters implement the account/password path only. Account creation, recovery, provider selection, passkeys, MFA, language switching, real file retrieval and credential verification are not implemented. Footer terms and privacy text are noninteractive, consistent with the existing offline starters. Document buttons open the page's own sign-in presentation; they do not contact a cloud provider. ## Shared interaction owner

[`interaction.js`](../src/starter_templates/interaction.js) owns intermediate navigation, native validation, focus, password visibility, final-submit locking and the call to `window.ruphish.submit(form)`. Catalog `Source::entry` embeds it before the closing body tag only for the six explicitly configured pages. Keep one closing body tag in each source. Exported/imported copies contain the complete script and require no catalog lookup. Directly opening the raw repository HTML does not assemble the script; use the catalog's prepared page preview.

The page uses only the existing final-submission event. Opening a file card, advancing the identifier screen, going back and toggling password visibility create no submission event. Back clears the password. During and after final submission the form cannot create a second observation; an uncertain delivery is retried with the collector's existing retry button and identity. Reopen a preview to start again after submitting. No real account password is checked and no field value is transmitted by this interaction script.

## Design choices and review

Microsoft uses Segoe UI with Arial fallback, dark `#1b1b1b` text, white panels, neutral `#f2f2f2` background and `#0067b8` actions. Google uses Arial, `#1f1f1f` text, white panels, `#f0f4f9` background and `#0b57d0` actions. Dropbox uses Arial, `#1e1919` text, white panels, `#f7f5f2` background and `#0061fe` actions. Form controls and headings are left-aligned; document cards identify sender, file and view permission. Layouts stack on narrow screens without animation. The sharing cards intentionally use file metadata rather than invented document contents.

Automated tests cover form interaction, privacy, prefill, branding, independent resource copies and catalog counts. Visual fidelity, mobile layout, actual browser sandbox enforcement and email-client rendering remain manual review tasks in [the repository checklist](../../../docs/contributing/testing/manual-ui.md).
