# Resource management

The sidebar orders Campaigns, Resources and Administration. The Resources navigation contains recipient groups, email templates, landing pages and sending profiles. Each resource belongs to the signed-in account. Campaigns and Analysis are disabled navigation placeholders until campaign execution and reporting are implemented. Administrator-only Users appears under Administration; the sidebar footer username button contains My account and Sign out.

Internal links use client-side routing inside a persistent sidebar and account shell. Back/Forward keeps normal history semantics, and unsaved resource edits are guarded before links, history traversal and document unload. Successful create/edit saves navigate to the saved resource view. Session revalidation runs on navigation and browser focus; identity changes still clear the authenticated view.

Open a resource from its searchable list to view saved details. Choose Edit to open `/<resource>/<id>/edit`, or Create to start an empty draft. Create and Save changes return to the saved resource view after success. A failed save retains the draft and its errors. Cancel changes stays at the bottom left and discards the draft, returning to the existing resource view or the overview for a new resource. Export JSON is available only on the saved resource view. Visual editing has its own Apply/Cancel controls. Leaving with unsaved source or an open visual session warns before navigation. Cancel, Delete and error feedback use the shared --color-danger token; successful outcomes retain status styling.

The UI sends the resource's ETag with saves. If another tab has changed it, saving fails with 412 and retains your draft. Keep the editor open while comparing the saved resource in another tab; reloading discards unsaved edits. Legacy clients may continue to make unconditional writes without If-Match. An existing duplicate name can still be edited without renaming it; new resources and renames cannot take another resource's name within the same account and resource type.

## Imports and content

Internal outbound connections require explicit IP addresses or CIDRs in `admin_server.allowed_internal_hosts`. An empty list denies loopback, private and other restricted destinations; it does not disable filtering. The conservative policy also requires explicit allowlisting for IPv6. This policy applies to site imports and configured outbound integrations, including each site redirect and its resolved addresses.

Import work is bounded before expensive parsing: CSV accepts at most 1,024 columns and 1,024 bytes per column-mapping key; HTML rewriting accepts at most 65,536 template actions and bounds intermediate/restored content to 8 MiB. Office XML parts are bounded to 8 MiB before marker scanning. Exceeding a limit rejects the operation without saving partial content.

Import is beside Create on each resource overview. Select a file with the native picker or paste content; landing pages also accept a website URL. Continue to create parses the input and opens a prefilled Create form for review. Resource JSON preserves supported fields and attachments; CSV supplies recipients; email supplies subject/HTML/plain text; HTML/site imports supply HTML only. No resource is persisted until Create succeeds. Import accepts one resource at a time: a top-level array or resource collection wrapper is rejected as a whole with IMPORT_BATCH_NOT_SUPPORTED. Recipient, attachment and header arrays inside one resource remain supported. Imported IDs, ownership and modification timestamps, including nested recipient/header IDs, are discarded.

The URL contains only a random draft ID, such as `/groups/new?draft=<id>`. The authenticated shell owns the in-memory draft and its review notes; the form edits the same value. No imported payload is placed in the URL, localStorage, sessionStorage or a server-side draft table. Save and leaving the form after Cancel/confirmed discard remove the entry; logout/account changes clear the shell. Reloading or closing the tab loses the draft. Missing, wrong-family or stale IDs show IMPORT_DRAFT_UNAVAILABLE with an Import again action, never an empty replacement form. The store allows at most eight retained imports.

CSV imports offer column mapping, rejected-row details and a downloadable error report. The first accepted row for each case-insensitive address is kept. Duplicate omissions and rejected rows remain visible on Create and require acknowledgement before saving. JSON/API group writes retain their existing address-identity behavior. A recipient edit in one group does not change another group's records. Generic import is absent from create/edit forms; it always starts a new resource from the overview.

Import errors display stable codes with actionable explanations: IMPORT_INVALID_JSON, IMPORT_WRONG_RESOURCE_TYPE, IMPORT_BATCH_NOT_SUPPORTED, IMPORT_UNSUPPORTED_FORMAT, IMPORT_TOO_LARGE, IMPORT_NO_VALID_RECIPIENTS, IMPORT_READ_FAILED, IMPORT_REQUEST_FAILED, IMPORT_DRAFT_UNAVAILABLE, IMPORT_ID_UNAVAILABLE and IMPORT_DRAFT_LIMIT. These are browser workflow codes; existing API HTTP statuses and legacy response envelopes remain unchanged.

Templates support HTML, a plain-text alternative, subject, visible From and attachments. The visible From field retains the legacy API name envelope_sender; the sending profile supplies the SMTP envelope sender. An empty subject and text-only or HTML-only templates remain supported. Raw-email import reads the subject and body alternatives; like the original API, it does not import MIME attachments automatically.

Landing pages always record supported submissions and password presence; the current API has no capture settings. The redirect remains an optional campaign default. Page checks warn about processed-form problems without rejecting advisory findings. See [landing pages](../user-guide/landing-pages.md) and [participant data](../user-guide/participant-data.md). Saved source remains unchanged by the public content policy. Resources referenced by unfinished campaigns cannot be deleted. Editing a resource affects its consumers, so duplicate it for an independent version.

Site imports validate TLS certificates and check the configured outbound policy before each connection and redirect. They preserve existing base semantics and use the final URL for relative resources. The legacy include_resources field remains accepted without resource inlining. Preview frames block scripts, remote resources and submissions; they do not produce campaign events.

## Connection and test email

Test connection verifies SMTP connectivity and authentication without submitting a message. Send test sends to one chosen recipient. Unsaved template/profile changes require Save and send test; a successful save remains saved even if delivery fails. Save and send test keeps the result dialog open; closing it returns to the saved resource view when no unsaved edits remain. Success means the SMTP server accepted the message, not that it reached an inbox. A connection loss after submission produces an unknown-outcome error; the application does not automatically retry it.

Port 25 is the default. Port 465 uses implicit TLS, and STARTTLS is used when the server advertises it. Certificates are verified unless the profile explicitly enables ignore_cert_errors. Authentication requires encryption except for loopback test services. Connections use the checked socket addresses while retaining the original hostname for TLS verification. Password values are not replaced with a masking placeholder in requests.

Named-template test emails persist preview state in email_requests. Public preview links are read-only, isolated documents; submissions are rejected and no campaign results, events or queue entries are created. Campaign delivery uses a durable queue; public tracking and presence-only submission handling are described in [domains and public interactions](domains-and-interactions.md).

## Limits and verification

Resource HTTP bodies are limited to 32 MiB including JSON/base64 overhead. Documents and CSV/MIME/site imports are limited to 8 MiB, individual decoded attachments to 16 MiB, and Office archives to 4,096 entries and 64 MiB expanded content. Groups/imports accept at most 100,000 records. The SMTP adapter permits four concurrent connection/submission operations. Limits reject the operation rather than saving or sending partial output.

Run the individual checks in [AGENTS.md](../../AGENTS.md). Real executable workflows live in tests/resource_process.rs, format and independent Go attachment cases in crates/ruphish-adapters/tests/resource_formats.rs, and browser draft workflows in tests/editor_workflow.rs. Browser appearance, keyboard interaction and layout remain manual acceptance tasks. See [dependency notices](resource-dependencies.md) for additional parser and transport dependencies.

Account navigation is consolidated in the sidebar footer username button. Its popup contains My account and Sign out; see [account screens](authentication.md#account-screens). The navigation list scrolls independently on desktop so the account control remains available.
