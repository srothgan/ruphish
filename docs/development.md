# Local development and verification

Run commands from this product directory. rust-toolchain.toml selects Rust 1.99.1 with rustfmt, Clippy, and wasm32-unknown-unknown; edition 2024 and supported Rust 1.99 are inherited by every member. Rustup may download missing selected components. Trunk's exact requirement is in Trunk.toml, and cargo-deny's and leptosfmt's required versions are in Cargo.toml workspace metadata. Add dependencies and install tools through CLI commands; keep Cargo.lock under version control.

## Direct checks

[Validation](validation.md) owns the change-specific catalog, direct commands, CI selection and nightly/release policy. [AGENTS.md](../AGENTS.md) provides completion rules. Run relevant commands directly; no local task runner is required. Node/npm are browser build/test tools, not server runtime dependencies.

## Formatting and editor setup

Install the required Leptos formatter from the product directory:

```sh
cargo install leptosfmt --version 0.1.33 --locked --profile dev
leptosfmt --version
```

The tool version must match `[workspace.metadata.tools]` in Cargo.toml. The formatter is a development executable, not an application dependency. Rustfmt is supplied by the pinned Rust toolchain. Check Rust formatting after Rust changes and Leptos formatting after markup changes; these commands apply formatting and then check the result:

```sh
leptosfmt crates/ruphish-ui/src crates/ruphish-ui/tests
cargo fmt --all
leptosfmt --check crates/ruphish-ui/src crates/ruphish-ui/tests
cargo fmt --all -- --check
```

The shared configurations use edition/style edition 2024 for Rust, a 100-column target width, four-space indentation and LF line endings. Rustfmt retains its default small-construct heuristics. Leptosfmt preserves attribute braces and closing-tag style. Long literals may exceed the width target. The Rust-source Git line-ending rule agrees with the formatters; byte-sensitive fixtures and SQL migration rules remain separate.

`rust-analyzer.toml` selects `leptosfmt --stdin --rustfmt` for editor formatting. Open the product directory as the editor workspace and ensure leptosfmt is on the editor process's PATH; restart the editor after installing it if necessary. Rust-analyzer clients that support project configuration use this file. If a client does not load it, set its `rust-analyzer.rustfmt.overrideCommand` workspace option to `["leptosfmt", "--stdin", "--rustfmt"]`. The direct CLI checks remain authoritative; editor format-on-save is optional. See the [formatter's editor integration guidance](https://github.com/bram209/leptosfmt#using-with-rust-analyzer).

Formatting does not replace review of complex markup: extract substantial handlers and transformations into named callbacks/functions when that improves clarity. Leptosfmt can drop ordinary comments inside embedded Rust expression blocks, so keep explanatory comments outside those blocks and review the formatting diff for preserved intent. Do not accept missing explanations or changed authored text merely because the formatter succeeded.

Use development builds for local work. Optimized release builds are reserved for final verification explicitly requested by the user.

## Tests and checks

tests/workspace.rs is attached to the native executable package and runs through the native cargo test command. It checks actual Cargo metadata and manifests: package boundaries, local-source containment, inherited lint/package settings, supported compiler series, and deliberate native/browser default-member separation. Compatibility tests now exercise real SQLite upgrades, stored passwords/templates, and loopback HTTP wire behavior. UI library workflows cover template import/export, cancellation and binary attachments; separate Node tests use actual CodeMirror state/history/completion APIs with the browser bridge's configuration. These are focused proofs, not full resource/authentication/campaign coverage.

The UI also has a WASM integration test for its actual Fetch request builder: cargo test -p ruphish-ui --test browser_requests --target wasm32-unknown-unknown --locked. It runs in Node using the matching wasm-bindgen-test-runner (install wasm-bindgen-cli 0.2.129 with Cargo CLI). It verifies bodyless GET/HEAD requests and JSON mutation bodies/headers; native server tests alone cannot catch JavaScript Request-construction errors. Browser appearance and interaction remain manual.

Original compatibility fixtures live in tests/fixtures/gophish-v0.12.1; additional Go-captured upgrade/wire/editor fixtures live in tests/fixtures/compatibility. Authentication fixtures in tests/fixtures/authentication preserve independent Go account API responses and an established bcrypt account database. The legacy map identifies implemented equivalents and their exact executable tests; remaining feature cases retain not_implemented status. Copy database fixtures into isolated temporary locations before mutating them. No browser automation or screenshot suite is configured; visual and UI interaction testing is performed manually.

Production code forbids unsafe code and denies accidental unwrap/expect/panic/exit/todo/unimplemented/dbg use. Clippy allows narrow assertion/setup patterns inside tests; the isolated executable-test harness has local unwrap/panic exemptions for setup and deadline assertions; production lint policy remains unchanged. Every member inherits shared lints. Rustfmt uses the pinned component and the shared rustfmt.toml; leptosfmt formats the UI macros using leptosfmt.toml.

## Browser assets

First install browser dependencies. Run node crates/ruphish-ui/web/build.mjs before direct WASM checks; Trunk.toml runs the same build-only generator automatically before compiling the UI and creates asset-manifest.json in staging afterward. The native server verifies every file against this manifest before readiness. This is asset generation, not a wrapper for checks. esbuild produces crates/ruphish-ui/web/generated/editor.js and the separate visual-frame JS/CSS/legal assets from the exact npm lockfile. The source-editor module must exist before WASM compilation because wasm-bindgen imports it; Trunk copies the visual assets for the isolated frame. Rebuild after changing editor sources or dependencies. Runtime package notices are preserved in web/THIRD-PARTY-NOTICES.txt and copied into the output; update them alongside dependency changes. No CDN or runtime npm install is used.

Trunk reads crates/ruphish-ui/index.html and its adjacent Cargo.toml, builds the wasm32-unknown-unknown binary using Cargo.lock, generates the matching wasm-bindgen JavaScript glue, and produces hashed files under dist/admin. Trunk owns dist/ and uses dist/.stage/ while building; the post-build hook generates the manifest and groups the completed output under admin/ before Trunk promotes it. The native server reads only dist/admin, so build intermediates are outside its asset root. Its wasm-bindgen tool is selected to match the locked crate, rather than maintained as a second manually synchronized version. Additional wasm-opt processing is explicitly disabled for this initial build; Rust release compilation and thin LTO still apply. Optimization/size decisions can be measured later.

Build with Trunk, then run the native executable and open its admin listener for functional UI testing. Account screens call the same-origin backend; standalone `trunk serve` is not configured for the nested admin distribution or authentication backend and cannot validate these flows. Never use stale dist output as proof of current source behavior; rebuild after UI changes. target/, dist/, local data/, .env and PERSONAL.md are ignored. Regression SQLite fixtures are deliberately not globally ignored.

Trunk 0.21.14 parses NO_COLOR as a boolean in both root and subcommand options, so NO_COLOR=1 can fail before a build starts even with a --no-color flag. Set `$env:NO_COLOR = 'true'` in PowerShell before direct Trunk commands, or use `NO_COLOR=true trunk build --locked` in a POSIX shell. This is a process-only value; do not change persistent environment settings.

## Dependency policy

deny.toml evaluates Windows/Linux/macOS native and browser graphs, explicitly allows reviewed permissive licenses and crates.io, rejects unknown registry/Git sources, and checks advisories/yanked packages. Duplicate versions are reported for review rather than globally denied because third-party version splits do not necessarily imply an actionable conflict. Avoid broad suppressions. No advisory ignore entries are configured. Network access is required for initial dependency/tool downloads and current advisory information; a network failure is a failed/unavailable check, not a clean audit.

Exact-version license exceptions in deny.toml identify the reviewed dependencies and reasons; do not broaden the general allowlist to silence a finding. TLS trust-data agreements and resource-parser notices are retained in [resource dependency notices](resource-dependencies.md). CodeMirror and Jodit runtime packages are MIT; their notices are preserved in the browser output. cargo-deny does not inspect npm dependencies; npm audit checks their advisory graph separately.

GitHub actions/state, releases, publishing, distribution packaging, and deployment are deferred. Completing local checks does not authorize any of those actions.

## Languages

Application text lives in `crates/ruphish-ui/locales/en.json` and `de.json`. `leptos_i18n` 0.6 generates checked translation keys in the UI build script. English is the default and fallback. `localization::provide` installs one context above the router; use `tr!` for reactive view text, `trs!` for shared control labels, and `t_string!` with a captured context inside reactive computations or callbacks. Translate received error codes once in the response handler and retain ordinary message strings; existing errors do not change language after display.

Account settings offer independent overrides for interface language (`en` or `de`), date/time format (a browser-supported BCP-47 locale such as `zh-CN`) and IANA time zone (such as `Europe/Berlin`). `ruphish_user_preferences` stores these against the authenticated account; `null` means use the current browser default, never a snapshot of detection. The self-service `GET`/`PUT /api/user-preferences` endpoint reads or replaces the caller's settings, validates input, enforces browser CSRF and rejects impersonated account changes. A save does not change authentication generations. Session bootstrap and revalidation load the overrides, so they follow the account across devices. Returning to the tab, restoring visibility or navigating within the application revalidates preferences without reloading the document. Existing browser-only language/time-zone entries are no longer authoritative and are not automatically copied into an account.

Before sign-in, language follows the browser's ordered language list, matching regional tags such as `de-DE`; unsupported languages fall back to English. Saved account language takes precedence after bootstrap. Date formatting follows its own override or browser formatting locale, and the time zone follows its own override or browser zone with UTC fallback. A Chinese format with a Berlin time zone therefore shows Berlin civil time using Chinese date presentation, independently of English or German interface text. Saved timestamps remain UTC; local date/time input continues to resolve through the selected IANA zone and existing daylight-saving validation. Docker and directly executed native servers serve the same WASM frontend; host/container locale and time-zone settings do not select browser presentation.

The profile form provides searchable single-choice pickers, compact reset buttons directly below each selector, a preview and a persisted `show_utc_offset` checkbox (true for existing accounts). Reset buttons include the detected browser value. Selector examples, the preview and application labels use the same formatter and numeric date components, with date order, separators and hour cycle supplied by the chosen locale; settings examples share one reference instant and selected zone. This replaces the former mismatch between numeric picker examples and written-out months in full timestamps. The time-zone picker enumerates Jiff’s available identifiers and shows current UTC offsets. The formatting picker uses the vendored Unicode CLDR 48.0.0 locale inventory, filters it through browser `Intl` support and domain validation, and displays localized language/region names with date/time examples. No free-text identifiers are required. The locale inventory’s source and Unicode license are retained in `web/THIRD-PARTY-NOTICES.txt`; `web/build.mjs` bundles it with the date formatter. Confirmed saves update text, the document language and date labels reactively without navigation; failed saves preserve the active settings and retain the draft for retry. Both catalogs cover the settings labels, validation and feedback. Authored content, resource names, template variables and wire values are not translated. Clean preference forms follow revalidated values; unsaved fields retain their own baseline and are not overwritten. A response started before a confirmed save cannot undo that save. Missing response fields are rejected instead of silently applying browser defaults; failed refreshes retain confirmed values and show localized stale-data feedback with retry in account settings.

To add an interface language, add its JSON catalog and native language name, register it with `Config::add_locale` in `crates/ruphish-ui/build.rs`, allow the language in `ruphish-domain/src/preferences.rs`, and import its `editor` section in `web/editor-i18n.mjs`. The selector and browser matching use the generated locale list. Keep keys and interpolation arguments aligned across catalogs; the catalog tests check them. Editor translation operates only on the application shell, outside the authored document, and preserves open editing sessions. CodeMirror phrases follow the current UI language. Jodit receives an explicit language and the bundled German dictionary when opened; vendor widgets retain that opening language until reopened (the controller has a TODO for safe in-place vendor language changes). New form-button defaults use a supported document language or the editor language; existing authored text is never retranslated. Run the browser checks above, including catalog and locale tests and the WASM request suite's preference-precedence, reactive-text and independent-formatting tests. Preference persistence and migration tests cover SQLite, MySQL and PostgreSQL, plus the executable HTTP boundary.


Application HTTP rejections add a stable `code` alongside the existing `success`, `message` and `data` fields, preserving status codes, legacy English messages and retry headers. CSV review rows also add a code without removing their original report fields. This is an intentional additive wire-contract change: strict clients must permit the new field. `ruphish-contracts/src/errors.rs` owns the public code vocabulary; handlers select codes from typed failure categories, and the frontend maps them through `leptos_i18n` to `CODE - translated message`. Unknown codes remain visible with a localized generic explanation. Resource validation and external delivery failures currently use category codes; their detailed diagnostics remain in the legacy API message. Debug rejection logs include the same code without request values. The HTTP error contract test checks compatibility, and the WASM test checks translation and unknown-code fallback.

Public submission feedback uses `crates/ruphish-adapters/src/landing-locales.json`, independent of the administrative frontend. It selects a supported page language, then the browser language list, then English. This changes only application-generated status notices, not authored content or the restricted submission payload.


## Shared management UI

Management pages use the Leptos components in crates/ruphish-ui/src/shared/components/ and their stylesheet, styles.css in that directory. Page width, headings, tables, search/count toolbars, form surfaces and fields, action buttons/links, save controls, footers, empty states and delete confirmation belong there. Keep resource-specific content in resources.css and account-specific controls in account.css; do not recreate user-table or user-form layout overrides. Feature modules retain their own wire types, validation, draft state and mutations. Shared components receive content and callbacks without knowing about API routes, roles or resource families.
