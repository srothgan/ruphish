Start with the first failing command. A failed build or unavailable service is a setup failure, not evidence that a test assertion failed. Keep local application databases and fixture credentials when repairing tools.

| Symptom | Check and fix | Verify |
| --- | --- | --- |
| Rust cannot find a linker | Install the native build tools described in [setup](index.md#prepare-your-tools), then reopen the terminal so PATH changes apply. | Rerun the failed Cargo command. |
| Trunk rejects `NO_COLOR` | Set it to the literal `true`, not `1`. | Rerun `trunk build --locked`. |
| A direct WASM check cannot find an imported browser module | Install browser npm dependencies, then run `node crates/ruphish-ui/web/build.mjs` from the repository root. Trunk normally runs this step for you. | Rerun the same WASM check. |
| Startup reports missing or stale administration assets | Check the working directory, run `trunk build --locked`, and restart. | Readiness returns `200` and the sign-in page loads. |
| The UI displays simulated responses | The last build may have enabled the `demo` feature. Rebuild with ordinary `trunk build --locked`. | Restart the native server and sign in to its real local account. |
| A listener cannot bind | Stop the other process using the configured port, or choose a free port in the development configuration. | Start again and use the new address. |
| The application opens unexpected data or uses unexpected settings | Check the explicit `--config` argument, working directory, and configured environment overrides. | Confirm startup uses the intended listeners and local database. |
| A filtered Rust test run passes with zero tests | Check the target and filter against `cargo test -p PACKAGE --test TARGET -- --list`, replacing the uppercase values. | Rerun and confirm the intended tests actually execute. |
| MySQL/PostgreSQL cases are ignored | These tests need explicit selection with `--ignored` and a prepared service. | Follow [database-provider tests](../testing/database-provider-tests.md). |
| Docs search is unavailable in the dev server | Pagefind's index is generated by a production site build. | [Build and preview the docs](../development-guides/documentation-and-website.md#preview-your-changes). |

## Windows process-test shutdown

Some Windows launchers pass an ignored Ctrl+C setting to their children. If a process test fails specifically while waiting for graceful shutdown, restore Ctrl+C handling in the launching PowerShell process, then rerun that test:

```powershell
Add-Type -TypeDefinition 'using System; using System.Runtime.InteropServices; public static class RuphishTestConsole { [DllImport("kernel32.dll", SetLastError=true)] public static extern bool SetConsoleCtrlHandler(IntPtr handler, bool add); }'
[RuphishTestConsole]::SetConsoleCtrlHandler([IntPtr]::Zero, $false)
```

This addresses the launcher setting. It does not excuse a shutdown failure that remains reproducible afterward.

## Fixture conflicts

The [acceptance fixture](../testing/local-acceptance-fixture.md) uses fixed loopback ports and a fixed Docker subnet. Run one instance per host. For disposable state, select a new absolute `RUPHISH_ACCEPTANCE_DATA_DIRECTORY` before initialization and keep it set for both Node and Compose commands. Changing this directory does not allocate different ports or another subnet.

Preserve existing application-lab data when stopping or rebuilding services. Record the exact command and redacted error if the documented recovery does not resolve the problem.
